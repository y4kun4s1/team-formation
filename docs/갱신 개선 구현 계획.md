# 화면 갱신 개선 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 다른 사람의 변경이 5초 안에 보이고, 변경이 없을 때는 화면을 다시 그리지 않으며, 한 번 그릴 때의 DB 왕복을 학생 약 8회, 관리자 약 10회 이하로 줄인다.

**Architecture:** DB 상태의 지문(변경 토큰)을 질의 하나로 읽고, 눈에 안 보이는 감시자 fragment가 2초마다 토큰을 확인해 바뀐 때만 앱 전체를 다시 그린다. 한 번 그릴 때 필요한 데이터는 `Service.snapshot()`이 연결 하나로 읽고, 모든 사람에게 같은 공통 데이터는 토큰을 키로 한 공유 캐시로 한 번만 읽는다.

**Tech Stack:** Streamlit 1.66.1(`st.fragment`, `st.cache_data`), psycopg3 + psycopg_pool, pytest + 로컬 PostgreSQL, Playwright.

**Spec:** `docs/갱신 개선 설계.md`

## Global Constraints

- 다른 사람의 변경이 내 화면에 보이기까지 5초 이하(DB 왕복 100~200ms 가정). 감시자 간격은 `POLL_SECONDS = 2`.
- 스키마(`schema.sql`)와 화면 요소의 key(공고 2.7절 표의 이름)는 바꾸지 않는다.
- 기존 개별 읽기 메서드(`get_student`, `teams`, `unassigned`, `is_closed`, `application_of`, `last_application`, `pending_for_team`, `votes_by`, `recent_ai_logs`)는 그대로 둔다.
- 화면 문구는 한국어, 화면에 키·DB 주소·비밀번호를 출력하지 않는다.
- 오류 문구 "DB에 접속하지 못했어요. 잠시 후 자동으로 다시 시도해요."는 그대로 쓴다.
- 지연 프록시는 시험 도구(`tests/`)에만 둔다. 제품 코드에 지연을 넣지 않는다.
- 커밋은 3개(Task 1, 2, 3)로 나누고, 각 커밋 끝에 `pytest` 전체가 통과해야 한다.

## Review Focus

1. 명단을 같은 인원 수로 다시 올린 경우(학생 수는 같고 id와 이름만 바뀜) 토큰이 바뀌어야 한다. → Task 1
2. DB가 잠시 끊겼다 돌아오면 사용자가 새로고침하지 않아도 화면이 복구되어야 한다. → Task 3
3. 관리자가 팀 수를 고르고 파일을 올린 상태에서 다른 사람이 변경해 화면이 다시 그려져도 입력값이 남아 있어야 한다. → Task 3
4. 공유 캐시에는 개인 정보(내 신청, 내 투표)가 들어가지 않아 다른 학생에게 섞이지 않아야 한다. → Task 2
5. 한 사람이 2~4초 간격으로 클릭하는 동안 다른 변경으로 화면이 계속 다시 그려져도 클릭이 하나도 씹히지 않아야 한다. → Task 3

**Interfaces:**
- Consumes: `Service.change_token() -> str`, `Service.common_view() -> CommonView`, `Service.snapshot(student_id, common=None) -> Snapshot`.
- Produces (`streamlit_app.py`):
  - `POLL_SECONDS = 2` (`REFRESH_SECONDS` 대체).
  - `_shared_token(_svc: Service) -> str` — `@st.cache_data(ttl=1, show_spinner=False)`.
  - `_shared_common(_svc: Service, token: str) -> CommonView` — `@st.cache_data(ttl=30, max_entries=4, show_spinner=False)`.
  - `watcher(svc: Service) -> None` — `@st.fragment(run_every=POLL_SECONDS)`. 토큰 읽기에 실패하면 아무것도 하지 않고, `_shared_token(svc) != st.session_state.get("seen_token")`이면 `st.rerun()`(앱 전체).
  - `render_student(svc, snap: Snapshot)`, `render_admin(svc, snap: Snapshot)`, `render_teams(svc, snap)`가 `Snapshot`을 받아 그리며 렌더 중에는 DB를 읽지 않는다. 학생 화면은 관리자 전용 데이터를 읽지 않는다.
  - `finish(result)`는 `st.rerun()`(앱 전체)을 호출한다.
  - 본문 아래에 `with st.container(key="watcher"):` 안에서 `watcher(svc)`를 부르고, 그 위에 `st.caption(f"마지막 변경 반영: {HH:MM:SS} (한국 시각)")`.

    - `test_other_users_change_appears_within_5_seconds`: 학생 A, B 두 페이지. B가 지원(빈 팀)하면 A 화면의 팀 카드에 B 이름이 5초 안에 나타남. 지원 시각부터 나타난 시각까지의 시간이 `< 5`.
