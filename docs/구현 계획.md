# 팀 편성 웹 앱 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 학생들이 스스로 팀을 꾸리고, 남은 학생은 무료 AI가 배정하며, 앱이 AI의 답을 규칙으로 검사하는 Streamlit 앱을 만든다.

**Architecture:** 규칙과 배정 검사는 DB와 AI에 의존하지 않는 순수 파이썬 모듈(`rules.py`, `assignment.py`)로 만든다. `service.py`가 트랜잭션과 잠금으로 이 모듈들을 묶고, `streamlit_app.py`는 화면과 `key`만 맡는다. AI 호출(`ai_client.py`)은 호출 함수를 바꿔 끼울 수 있게 만들어 가짜 AI로 테스트한다.

**Tech Stack:** Python 3.11+, Streamlit(버전 고정), psycopg 3 + psycopg_pool, bcrypt, requests, python-dotenv, pytest, 테스트용 로컬 PostgreSQL, GitHub Actions

**Spec:** `docs/PRD.md` (작업 폴더: 클라우드의 `/home/claude/team-formation/`, 모듈은 저장소 루트에 둔다. 배포 파일은 `streamlit_app.py`)

## Global Constraints

- 역할 6개: `기획자`, `웹 프로그래머`, `프론트엔드 디자이너`, `테스터`, `보고서 작성자`, `발표자`. 필수 포함 역할은 `기획자`와 `웹 프로그래머`(서로 다른 사람).
- 팀은 2~4명, 팀 안에서 주 역할 중복 없음. 학생 비밀번호는 `1234`, 관리자 학번은 `admin`.
- `result`와 `assign_status`의 안내 첫 단어는 `승인`, `대기`, `거절`, `막힘` 중 하나.
- 화면 `key`는 PRD 5절 표 그대로(영문, 숫자, 밑줄만). 하나라도 다르면 −5점.
- 모든 테이블 이름은 `tf_`로 시작. 비밀번호는 bcrypt 해시로만 저장.
- AI 모델은 `:free`만. `openrouter/free` 라우터 금지. 모델마다 응답 전체 120초 제한, 전체 배정은 10분 이내.
- 명단 CSV는 `utf-8-sig`로 읽는다. 시각은 한국 시각(UTC+9)으로 보여준다. 자동 갱신 간격은 5초 이하.
- 키, `DATABASE_URL`, 관리자 비밀번호는 코드, 커밋, 화면, 로그에 넣지 않는다. 실제 수강생 이름과 학번도 쓰지 않는다.
- 커밋 메시지는 시스템이 정한 `Co-Authored-By`와 `Claude-Session` 줄로 끝낸다.

## Review Focus

- 명단 CSV에 BOM이 있거나 `sub_roles`가 비었거나 `;`로 2개인 경우, 열이 틀린 경우: 앞의 둘은 읽히고 뒤는 "막힘: 이유"로 안내한다. (Task 2)
- 로그인 때 학번이나 비밀번호 앞뒤 공백, 없는 학번, 빈 비밀번호: 모두 "막힘"으로 거절하고 예외를 내지 않는다. (Task 6)
- 두 브라우저에서 같은 학생이 동시에 다른 팀에 지원: 대기 중인 지원은 하나만 남는다. (Task 6)
- AI가 JSON 앞뒤에 설명문이나 코드 펜스를 붙이거나 없는 학번을 넣은 경우: 파싱하거나 검사에서 걸러 다음 모델로 넘어간다. (Task 5)
- 명단을 다시 올려서 지워진 학생의 세션이 남아 있는 경우: 오류 화면 대신 로그인 화면으로 돌아간다. (Task 7)
