# PRD: 팀을 편성하는 웹 앱

작성일: 2026-10-27 · 상태: 검토 대기 (구현 전)

## 1. 목적과 성공 기준

학생들이 팀 프로젝트의 팀을 스스로 꾸리는 Streamlit 웹 앱을 만든다. 팀에 못 들어간 학생은 무료 AI가 배정을 돕고, 앱이 AI의 답을 규칙으로 검사한다. 중간 과제 공고(11/2 23:59 마감)의 1~6장을 따른다.

성공 기준은 다음과 같다.

- 공개하지 않은 채점 시나리오 3개(쉬움, 중간, 어려움)에서 모든 단계의 결과 안내(`result`)가 기대 결과와 같다.
- 2.7절 표의 화면 요소 `key`를 하나도 빠뜨리지 않는다(빠지면 자동 채점이 멈춘다).
- 확정 후 모든 팀이 2~4명이고, 팀마다 서로 다른 사람의 기획자와 웹 프로그래머가 있으며, 주 역할 중복이 없다.
- 감점 항목 21개(공고 6.3절)에 걸리지 않는다.

## 2. 범위와 제약

- 개인 과제이며 Claude 사용은 허용된다.
- 앱이 쓰는 AI는 OpenRouter의 `:free` 모델만 쓴다. 유료 모델과 크레딧 구매는 쓰지 않는다. `openrouter/free` 라우터는 감점 대상이라 쓰지 않는다.
- 무료 모델 한도는 분당 20회, 하루 50회다. 채점 기간(11/3~11/4)에는 채점자가 지수의 키로 AI를 부르므로, 하루 한도 50회 중 30회 이상을 비워둔다(직접 AI 테스트를 하지 않는다). 이 한도는 DB 요청과 별개이며, GitHub Actions의 일일 DB 질의는 AI를 부르지 않는다.
- 인프라는 모두 무료이다: Streamlit Community Cloud, Supabase 무료 프로젝트(6장 실습 프로젝트 재사용), GitHub, GitHub Actions.
- 실제 학생 이름과 학번은 쓰지 않는다. 비밀번호는 해시로 저장한다.

## 3. 사용자와 기능

### 3.1 학생
- 학번과 비밀번호(1234)로 로그인한다.
- 팀 목록, 팀원, 팀원의 주 역할과 보조 역할을 본다. 내 팀에는 "내 팀"이 붙는다. 팀이 없으면 "아직 팀이 없음"을 본다.
- 팀에 지원한다. 내 팀에 들어온 지원에 찬성 또는 거부를 누른다(한 번 누르면 바꿀 수 없다).

### 3.2 관리자(학번 `admin`)
- 명단 CSV(utf-8-sig, BOM 허용)와 팀 수로 앱 상태를 처음부터 만든다.
- 모집을 마감한다.
- 팀이 없는 학생을 확인하고 AI 배정을 실행한다.
- 검사를 통과한 배정안을 확인하고 확정한다.
- 관리자 비밀번호는 `ADMIN_PASSWORD`에서 읽어 시작할 때 만들거나 갱신한다. 명단을 다시 올려도 관리자 계정은 남는다.

## 4. 규칙

### 4.1 팀 규칙
- 마감 뒤 확정된 팀은 모두 2~4명이다.
- 팀 안에서 주 역할이 같은 학생이 2명 이상이면 안 된다.
- 모든 팀에 기획자와 웹 프로그래머를 맡을 서로 다른 학생이 있어야 한다. 주 역할이나 보조 역할로 맡을 수 있다.

### 4.2 지원 검사 (지원 단추를 누르는 순간)
어기면 지원을 접수하지 않고 `result`에 "막힘: 이유"를 보여준다. DB에는 기록하지 않는다. 검사 순서는 다음과 같다.

1. 모집이 마감됐는가
2. 이미 팀이 있는가
3. 결과를 기다리는 지원이 있는가
4. 팀이 4명으로 꽉 찼는가
5. 주 역할이 같은 팀원이 있는가
6. 필수 포함 역할 자리가 모자라는가

6번의 계산은 다음과 같다. 팀원 중 기획자를 맡을 수 있는 사람과 웹 프로그래머를 맡을 수 있는 사람을 서로 다른 사람으로 짝지을 수 있는 최대 수(0~2)를 구한다. 지원자가 들어간 뒤 `4 - 인원`이 `2 - 짝지은 수`보다 작으면 막는다.

### 4.3 투표와 승인
- 빈 팀에 지원하면 바로 승인된다.
- 투표자는 투표하는 때의 팀원이다. 한 명이라도 거부하면 다른 사람의 투표를 기다리지 않고 바로 거절한다.
- 모든 현재 팀원이 찬성하면 승인 직전에 4.2절의 4~6번 규칙을 다시 검사한다. 어기면 거절하고 이유를 남긴다. 처리 순서는 투표가 끝난 순서이다.
- 아직 투표하지 않은 팀원이 있으면 대기이다.
- 지원 결과 안내(`result`)의 첫 단어는 승인, 대기, 거절, 막힘 중 하나이다.

### 4.4 마감
- 대기 중인 지원은 모두 거절한다.
- 1명뿐인 팀의 학생은 팀에서 빠져 "팀이 없는 학생"이 된다.
- 마감 뒤에는 지원과 투표를 할 수 없다.

### 4.5 AI 배정
1. 먼저 AI 없이 규칙을 지키는 배정이 있는지 탐색한다. 없으면 AI를 부르지 않고 `assign_status`에 "규칙을 지키는 배정이 없음"과 이유(예: 팀3에 웹 프로그래머를 맡을 학생이 없음)를 보여준다.
2. 있으면 1차, 2차, 3차 모델 순으로 부른다. 모델마다 응답 전체를 120초로 제한한다(스트리밍으로 받으며 시간을 직접 잰다). 오류, 429, 빈 응답, 시간 초과, 검사 실패는 모두 다음 모델로 넘어간다.
3. 응답은 아래 다섯 가지로 검사한다.
   - 팀이 없는 학생이 빠짐없이 배정됐다.
   - 한 학생이 한 팀에만 배정됐다.
   - 모든 팀이 2~4명이다.
   - 팀 안에 주 역할 중복이 없다.
   - 필수 포함 역할이 채워진다.
   이미 팀에 있는 학생은 옮기지 않는다.
4. 3차 모델까지 실패하면 앱이 직접 규칙을 모두 만족하는 배정을 끝까지 찾는다(백트래킹).
5. 검사를 통과한 배정만 관리자에게 보여주고, 확정하면 한 번의 트랜잭션으로 저장한다.
6. 대기 중에는 `assign_status`에 "몇 차 모델의 응답을 기다리는 중"을 보여준다. 전체 처리는 10분을 넘지 않는다(최악 120초 × 3 + 직접 배정).

화면 동작은 다음과 같다.

- 팀이 있거나, 결과를 기다리는 지원이 있거나, 모집이 마감됐으면 지원 단추를 숨긴다.
- 이미 투표한 지원은 찬성과 거부 단추를 숨기고 "내 투표: 찬성"처럼 보여준다.
- 로그인 뒤에는 눈에 안 보이는 감시자(`st.fragment(run_every=2)`)가 DB의 변경 토큰만 2초마다 확인하고, 바뀌었을 때만 새 데이터를 읽어 화면을 다시 그린다(`docs/갱신 개선 설계.md`). 마지막 `result`는 세션에 저장해서 다시 그려도 사라지지 않게 한다.
- 시각은 한국 시각으로 바꿔서 보여준다.
- 한글 `key`는 쓰지 않는다.

## 6. 데이터

모든 테이블 이름은 `tf_`로 시작한다. 테이블은 `schema.sql`로 만들고, 앱이 시작할 때 같은 파일을 실행해서 파일과 실제 DB가 어긋나지 않게 한다.

| 테이블 | 열 | 비고 |
|---|---|---|
| `tf_students` | id, student_no(유일), name, main_role, password_hash, is_admin | main_role은 6개 역할만 허용(check) |
| `tf_student_sub_roles` | student_id, role | 학생당 0~2행 |
| `tf_teams` | id, name(유일) | |
| `tf_members` | team_id, slot_no(1~4), student_id(유일) | `(team_id, slot_no)`가 기본 키 |
| `tf_applications` | id, team_id, student_id, status(대기/승인/거절), reason, created_at | 상태가 '대기'인 지원은 학생당 하나(부분 유일 인덱스) |
| `tf_votes` | application_id, voter_id, vote(찬성/거부), voted_at | `(application_id, voter_id)`가 기본 키 |
| `tf_settings` | key, value | 마감 여부 등 |
| `tf_ai_logs` | id, model, status, elapsed_ms, error_summary, created_at | AI 호출 기록(공고가 허용한 확장) |

동시성은 다음과 같이 다룬다.

- 지원, 투표, 승인은 팀 행에 `SELECT … FOR UPDATE` 잠금을 걸고 한 번에 하나씩 처리한다.
- 마지막 자리에 두 명이 동시에 들어오면 DB 유일성 제약이 먼저 도착한 학생만 기록한다.
- 연결은 `st.cache_resource`로 연결 풀을 한 번만 만들고 모든 질의에서 재사용한다. 끊기면 다시 맺는다.
- 명단 올리기(`admin_start`)는 한 번의 트랜잭션으로 지원, 투표, 팀원, 팀, 학생을 지우고 새로 만든다. 관리자 계정은 남긴다.

## 7. 기능별 난이도 선택 (공고 3장)

| 기능 | 선택 |
|---|---|
| 다른 사람의 변경 보기 | 어려운 해결: 변경 토큰을 `st.fragment(run_every=2)` 감시자가 확인하고 바뀌었을 때만 다시 그린다. 자동 갱신이 입력을 방해하면 쉬운 해결(`refresh` 단추)로 내린다. |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결: 지원 단계에서 자리가 모자라는 지원을 막는다. |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결: 승인 직전 재검사, 투표가 끝난 순서로 처리 |
| 마지막 자리에 두 명이 동시에 | 어려운 해결: DB 유일성 제약 |
| AI 응답이 늦을 때 | 어려운 해결: 모델마다 응답 전체 120초 제한 |
| 3차 모델까지 실패 | 어려운 해결: 백트래킹으로 규칙을 지키는 배정을 끝까지 찾음 |
| AI 대기 중 화면 | 어려운 해결: 몇 차 모델을 기다리는지 표시 |
| DB(Supabase) 일시정지 | 어려운 해결: GitHub Actions가 매일 DB에 가벼운 질의를 한 번 보냄 |

## 8. 보안과 키 관리

- `OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD`는 `.env`(로컬)와 Streamlit Secrets(배포), GitHub Secrets(`DATABASE_URL`만)에 둔다. 코드와 커밋에는 넣지 않는다.
- `.env`는 `.gitignore`에 넣는다. 키가 들어 있는지 확인할 때는 "있음/없음"만 출력한다.
- 화면과 로그에 키나 DB 주소를 출력하지 않는다. 오류는 안전한 문장으로 바꿔서 보여준다.
- 비밀번호는 bcrypt 해시로 저장하고 로그인할 때 입력값을 같은 방식으로 비교한다.
- 관리자 기능은 실행할 때마다 서버 쪽에서 관리자인지 확인한다.
- 실제 수강생의 이름과 학번은 명단, 코드, 문서, 화면 캡처에 쓰지 않는다.

## 9. 배포와 운영

- Streamlit Community Cloud에 비공개 깃허브 저장소로 배포한다. 배포 뒤 앱 공유 설정은 "This app is public and searchable"로 바꾸고, 시크릿 창에서 로그인 화면이 보이는지 확인한다.
- 저장소는 11/3(화) 09:00까지 공개로 바꾼다.
- 마감 이후에는 커밋하지 않는다(커밋하면 배포한 앱이 바뀌어 감점 1번).
- `.github/workflows/keepalive.yml`이 매일 DB에 가벼운 질의를 보낸다. 이와 별개로 11/2, 11/3, 11/5 아침에 직접 앱에 접속해 확인한다.
- 제출물: 저장소 주소, 배포 주소, 관리자 비밀번호(e-class 제출 칸에만), `README.md`, 커밋된 파일만 담은 `{학번}.zip`(`.env` 없음)

## 10. 테스트 계획

1. 규칙 단위 테스트: 필수 역할 짝짓기, 지원 검사 6가지, 승인 직전 재검사, 배정 검사 5가지, 백트래킹과 "배정 없음" 이유
2. 연습 시나리오 3개 재현: 부록의 단계를 코드로 옮겨 매 단계 `result` 첫 단어를 기대 결과와 비교한다. 명단 순서를 바꾼 변형도 돌린다.
3. 가짜 AI 테스트: 시간 초과, 429, 빈 응답, 틀린 배정, 정상 응답으로 1→2→3차 전환과 직접 배정을 확인한다.
4. DB 동시성 테스트: 임시 PostgreSQL에서 여러 스레드가 같은 자리에 동시에 지원해 한 명만 기록되는지 확인한다.
5. 화면 테스트: Streamlit `AppTest`와 브라우저로 2.7절의 `key`가 모두 나타나는지 확인한다.
6. 배포 후 실제 확인(지수 님이 직접): 실제 무료 모델로 연습 시나리오 3개를 돌리고, README 5~7항에 쓸 실패 사례와 화면 근거를 모은다. 사례를 꾸며 쓰지 않는다.

## 11. 열린 문제 (구현 때 확인)

- 1차, 2차, 3차 모델의 최종 선택: 후보는 `poolside/laguna-s-2.1:free`, `google/gemma-4-31b-it:free`, `nvidia/nemotron-3.5-lightning:free`. OpenRouter 모델 목록으로 지금도 유효한지 확인한다.
- Supabase 직접 연결 주소가 IPv6만 지원하면 Streamlit Cloud와 GitHub Actions에서는 풀러(IPv4) 주소를 써야 한다.
- 설치한 Streamlit 버전에서 `st.container(key=...)`와 `st.fragment(run_every=...)`가 되는지, AI 호출 중 자동 갱신과 충돌하지 않는지 확인한다.
- 6장 실습의 Supabase 프로젝트를 재사용하는지 확인한다(새로 만들지 않는다).
